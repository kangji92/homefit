# 개발 호재 — 그룹·필터 + 지역 적합도 (설계)

> 이 문서는 "개발 호재"(개발예정지 + 정비사업 + 철도 등) 묶음과, 정비사업 구역에 **지역 축
> 적합도**를 부여하는 설계의 단일 진실 소스다. vision의 비점수 원칙을 **정교화**한다.

## 1. 배경 / 결정
- 사용자는 개발예정지·정비사업·철도 등 개발 정보를 **"개발 호재"** 로 묶어 chip 필터로 보고 싶어 한다.
- 지금까지 정비사업(DevelopmentArea)은 **비점수 판단보조**였다. 그러나 정비사업 구역도 **좌표가 있어
  위치·통근·학군 같은 "지금 확인 가능한 지역 축"** 은 결정적으로 판단·점수화할 수 있다.

## 2. vision 정교화 (핵심)
비점수 원칙을 **"개발 정보 전부 비점수"** 가 아니라 아래로 정교화한다.

| 축 | 점수화 | 근거 |
|---|---|---|
| 위치·통근·학군·역세권·인프라·환경 (지역 축) | **허용**(결정적) | 좌표·거리·현재 시설 기반 사실 |
| 미래 개발 성과 (세대수·분양가·완성 후 가치·"유망도") | **금지** | 예측·투자성 → vision 위반 |

즉 fitScore 오염 금지는 **"미래 개발 성과 한정"**. 지역 축은 개발예정지/정비사업 모두에 부여 가능.
"개발 호재" 명칭은 **정보 프레이밍**으로만 쓰고, "가격 예측·투자 추천 아님 · 판단 보조" 고지를 항상 동반.

## 3. 지역 적합도 (Development Local Fit)
- 대상: **면·구역형**(정비사업=재개발/재건축, 개발예정지=신도시/택지). **철도(선)는 제외** — 지역이
  아니라 접근성 호재라 점수보다 정보.
- 입력: 구역에 curated **지역 축 seed** `localMetrics { education, transit, infrastructure, environment }`
  (0~100, rubric seed) + 지역 통근 프로필. **미래 성과(세대·분양가)는 입력에서 제외.**
- 산출: `computeDevelopmentLocalFit(priorities, area)` — priorities 가중으로 지역 축만 가중평균(결정적).
  결과 라벨은 반드시 **"지역 적합도(위치·교통·학군 기준) · 개발 성과 아님"**.
- 개발예정지(Area)는 기존 `computeAreaFit`(areaMetrics) 유지 — 이미 지역 축 점수다.

### 비목표 (하지 않는 것)
- 정비사업의 세대수·분양가·완성 후 시세·"얼마나 호재냐"를 점수에 반영하지 않는다.
- 좌표→통근 실시간 지도계산은 하지 않는다(mock/seed 통근 프로필 사용).
- 투자수익률·순위·추천은 없다.

## 4. IA / UI
- 탐색: "개발예정지" + "정비사업" 두 탭 → **"개발 호재" 한 탭 + 카테고리 chip**(정비·철도·신도시).
  chip은 `title` 툴팁 + "판단 보조 · 점수 아님(성과)" 고지.
- 카드: 지역 적합도 seed가 있는 구역/개발예정지엔 **적합도 게이지**(라벨: 지역 축). seed 없으면 게이지
  없이 정보만. 철도는 항상 정보만.
- 홈 퀵메뉴: 정비사업·개발예정지 → "개발 호재" 진입으로 통합 가능.

## 5. 데이터
- `DevelopmentArea.localMetrics?`(seed) 추가 — 우선 안양 주요 구역부터 큐레이션(rubric seed, 실측 아님).
  seed 없는 구역은 점수 없이 정보만(정직).
- 지역 통근: 기존 안양 mock 통근 프로필 재사용.

## 6. 단계
1. (이 문서 검토)
2. 도메인: `localMetrics` 타입 + `computeDevelopmentLocalFit` (+ 단위 테스트).
3. 데이터: 안양 주요 구역 seed.
4. UI: 개발 호재 탭 + chip + 게이지(라벨) + 고지.
5. vision 문서에 §2 정교화 반영.
