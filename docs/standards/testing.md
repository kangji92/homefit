# 테스트 표준

Vitest + React Testing Library 기준. (E2E는 `e2e.md`)

## 원칙

- **`domain/`(적합도·필터·정렬) 순수 함수는 최우선 테스트 대상**이며 높은 커버리지를 유지한다.
  `scoring.md` §7 워크드 예시를 기대값 기준으로 사용한다.
- **모든 컴포넌트는 최소 1개의 렌더 테스트**를 가진다.
- **사용자 관점**으로 검증한다 — `getByRole`·`getByLabelText` 등 접근성 쿼리. 구현 세부(클래스명·내부 상태)에 의존하지 않는다.
- 상호작용은 `@testing-library/user-event`로 검증한다.
- 커버리지 목표는 **80% 이상**.

## 무엇을 테스트하나

- **도메인**: 정규화식 경계값(0/100/구간 전환점), 가중치 정규화(합0 폴백), `sortByFit`(탈락 후보가 통과 후보 위로 못 올라옴), 절대조건 필터.
- 렌더링: 필수 콘텐츠·역할이 나타나는가.
- 상호작용: 클릭·입력 시 콜백/상태가 기대대로 동작하는가.
- 조건부·경계: variant·disabled·빈 값·탈락 등.

## 배치

- 컴포넌트 테스트는 컴포넌트 폴더에(`<Name>.test.tsx`).
- 도메인 테스트는 대상 옆에(`src/domain/scoring/*.test.ts`).
